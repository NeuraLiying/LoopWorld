# 迷宫记忆模型：真实自回归（self-forcing 式）训练设计 · 2026-10-15

## 动机
诊断（`maze_mem_diagnosis_20261014.md`）显示 oracle 记忆比自身预测记忆高 11 dB，说明问题是训练/测试不匹配：训练时只见过 GT 积分出的干净记忆，测试时记忆里写的是模型自己的预测。本方案让训练用的上下文也由模型自己生成。

## 方案：流式 rollout（`scripts/run_maze_v2_sf_train.py`，新文件）
- 维护 B 个常驻 episode 槽位。每个槽位保存：迷宫、当前帧 c、一个 PointMemory2（用模型自己生成的帧积分，按课程比例混入 GT）、最后一帧的自身预测。
- 每个训练步，对每个槽位取目标帧 t=c+1：
  1. 构造上下文：slot0 = 记忆重投影到 t 的相机；slot1 = 第 c 帧，以概率 p_own 用自身预测，否则用 GT。动作条件保持不变。
  2. 在这个上下文下，对 GT 目标帧算去噪损失（有梯度）。
  3. 用**同一个上下文**做一次无梯度采样，得到 t 的自身预测。采样用当前权重，S_roll 步、R_roll 次循环。
  4. 每 `stride` 帧把预测积分进记忆，以概率 p_own 用自身预测，否则用 GT；同时更新 prev。走到 episode 末尾就换一个新迷宫，从 c=0（GT 首帧）重新开始。
- 槽位的起始帧随机，并先用 GT 帧暖启动记忆，这样同一 batch 里的 t 不会同步。
- 课程：p_own 在前 N 步从 p_start 线性升到 p_end。
- 代价：每个训练步只多一次无梯度采样，而不是对每个样本重放整条轨迹。缺点是记忆里的帧来自几步之前的旧权重（stale），这一点可以接受。

## Splat 改进（`loopworld/geom_memory2.py`，新文件；v1 未改）
- 主 splat 用 1×1 最近像素（精确）。再用一层 2×2 footprint，只填补主 splat 留下的空洞；z-buffer 仍然生效。
- 点数上限 30 万（v1 是 12 万）。积分 stride 可配置。
- 3×3 补洞（≥6 个有效邻居时取最近深度）实现为可选项，默认**关闭**。
- GT 积分记忆、8 个迷宫的实测（每帧都算，不只是回访帧）：

| 变体 | 覆盖率 | 覆盖区内提示 PSNR |
|---|---|---|
| v1（1×1，12 万点） | 43.7% | 26.45 |
| v2，1×1，30 万点 | 47.0% | 26.85 |
| **v2，2×2 补洞 splat（默认）** | **69.9%** | **26.05** |
| v2，2×2 + 3×3 补洞 | 72.0% | 25.12 |

补洞只多出 2% 覆盖，却让提示 PSNR 掉 1 dB，所以默认不开。

## 冒烟（200 步，B16，roll S2 R2，课程 150 步内 p_own 从 0.2 升到 0.9）
- 无 NaN；1.85 it/s；显存 20.1 GiB。各部分耗时占比：训练 73%，rollout 21%，上下文构造 5%，积分 1%。
- held-out AR（8 个迷宫）：17.66 → 16.89 → 15.40；1-8 段 30.3 → 21.5。L100 从 0.009 升到 0.021。
- 判断：课程太快；而且 S2R2 的 rollout 质量远低于评测用的 S5R4，训练里的上下文比测试时更脏（反向的不匹配）。
- 调整：正式版 rollout 改为 **S3 R4**，课程放慢到 6000 步、p_end 降到 0.8。
- 在 S3 R4 设置下 profile 了 B14：17.3 GiB，8.5 samples/s；耗时占比：训练 40%，rollout 30%，上下文 28%。B16–18 的 profile 被其他用户同时占用 GPU5 显存干扰，结果无效。
