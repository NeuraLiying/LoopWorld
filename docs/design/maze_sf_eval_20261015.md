## 3. 关键结论
1. **Self-forcing 有效但幅度有限**：own AR 从 17.5 升到 19.0（+1.5 dB），回访 vs GT 从 17.0 升到 19.05（+2 dB），比 action 基线高 +2.8 dB 和 +3.3 dB。提升主要在远段：33-64 段 +1.4 dB，65-127 段 +2.2 dB。1-8 段反而比 mem run 低约 1.5 dB（31.4 → 29.9），这是用 rollout 上下文训练、牺牲 teacher-forcing 精度的代价。
2. **模型用好记忆的能力变强了**：oracle_mem 从 28.6 升到 31.7，9-32 段从 22.0 升到 29.3。部分原因是 v2 splat 覆盖更高（44% → 70%）。
3. **own 和 oracle 的差距仍有约 12.7 dB**，瓶颈依旧是记忆里写入的是错误预测（自身预测积分的提示 PSNR 只有 18.3，GT 积分是 27.8）。视频中常见的失败：转弯时正前方本应出现墙，模型却生成了延伸的走廊（见 `sf_frame8.png`，maze 600000 第 96 帧，回访时 PSNR 只有 10）。这段错误几何被写进记忆后，下一次回访会继续复现。也就是说，错误来源是"首访就生成了错误的拓扑/墙位"，而不是漂移。
4. "回访 vs 自身"约 24，明显低于 action 基线的 37。基线是"一致地错"，现在模型更愿意根据记忆和动作修正画面。

## 5. 为什么 AbsRel（均值）几乎没变（0.52 → 0.50）
- **中位数其实大幅改善**：mem run 是 0.028，SF 降到 0.006。大多数像素的深度很准，尺度中位数 pred/GT = 1.000，不存在尺度偏差。
- **均值被重尾主导**：rel>1 的像素约占 8%，却贡献了 82% 的 AbsRel 总和。这些像素集中在 **GT 近处（z<2）**：z<2 区间的均值是 0.58，中位数只有约 0.003。
- 原因是**几何/拓扑错误**：GT 是近墙（z 约 0.8），模型预测成远处走廊（z 4–8），甚至无效深度（3.5% 的像素被解码为 z_far=12）。AbsRel 按 |Δz|/z_gt 计算，近处 GT 被预测成远处时，单个像素就能贡献 5–15。去掉预测无效深度的像素后，均值降到 0.18。
- 反向错误也存在：GT 是天空（无命中）的像素里，有 22% 被预测成了表面（不计入 AbsRel，但能说明墙/天空边界错误）。
- 结论：AbsRel 均值主要反映"墙在不在"这种拓扑错误，和 PSNR 失败的帧高度重合。所以它不是深度精度问题，也不是编码或尺度 bug。oracle_mem 下均值降到 0.03 也印证了这一点。建议以后同时报中位数、δ<1.25，以及墙/天空 mask 的 IoU。

## 6. 下一步建议（待批准）
- 首访拓扑错误是主因，单靠记忆无法纠正"从未见过的墙"。可以考虑：
  - (a) 加强动作和几何的一致性，例如让转弯时贴近墙的帧在训练中出现得更多；
  - (b) 训练时提高 rollout 质量和比例（p_own 课程更慢、加长训练），因为曲线已经基本饱和，这条收益有限；
  - (c) 在记忆里存置信度，让低置信区域不覆盖新观察；
  - (d) 评测改用中位数 AbsRel / δ1 指标。
